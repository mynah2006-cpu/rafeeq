1. PROJECT CONCEPT AND OVERVIEW
================================================================================

NAME: Rafeeq (Arabic: rafeeq = companion / friend)

WHAT IS IT:
Rafeeq is a web-based AI patient companion for hospital and healthcare settings.
Target users:
  - Children (frightened or lonely in hospitals)
  - Elderly patients (difficulty with complex technology)

The app presents as an animated talking AI face on a tablet/kiosk in a patient
room. Patients speak naturally; Rafeeq responds with voice. Voice-first design
requires no reading or typing ability.

There is also a STAFF DASHBOARD for nurses/doctors showing patient wellbeing
summaries, pain levels, mood data, and critical alerts from AI conversations.

DUAL VIEW ARCHITECTURE:
  1. COMPANION MODE - animated face, mic button, conversation transcript.
     Dark background, neon cyan color scheme. For patients.
  2. STAFF DASHBOARD - clinical data: patient table, alerts, pain charts.
     For hospital staff only.

Both views are toggled with a single button in the top-right corner.

PHASE STATUS:
Code comments say 'Phase 2: Voice Pipeline Active'. Phase 2 means the full
STT -> LLM -> TTS pipeline is wired and operational.

2. SYSTEM REQUIREMENTS
================================================================================

RUNTIME (Browser):
  - Chrome 33+, Edge 79+, or Safari 14.1+ (Web Speech API required)
  - Microphone access permission required
  - JavaScript enabled
  - Audio output device (speakers/headphones) for TTS

DEVELOPMENT:
  - Node.js 18+ (LTS recommended)
  - npm 9+
  - Internet connection (Google Fonts + LLM API calls)

BROWSER COMPATIBILITY:
  Web Speech API is NOT supported in Firefox. The app handles this gracefully
  by disabling the mic button and showing an error message. Face animations
  and the dashboard work in all browsers.

SUPPORTED LANGUAGES:
  - English (en-US) - primary
  - Arabic (ar/ar-SA) - auto-detected from speech character content

7. ARCHITECTURE OVERVIEW
================================================================================

FEATURE-BASED ARCHITECTURE:
  1. voice     - STT + LLM + TTS pipeline
  2. face      - Animated SVG companion face
  3. dashboard - Staff clinical view
  4. emergency - Emergency detection and overlay

SHARED LAYER:
  AudioVisualizer, ParticleBackground, SplashOverlay, StatusBar,
  soundEffects - shared across features.

STATE MANAGEMENT:
  Two Zustand stores. No React Context, no prop drilling.
  faceStore:  all face animation properties
  voiceStore: voice pipeline state (conversation, errors, emergency)

DATA FLOW IN COMPANION MODE:
  User speaks
  -> Web Speech API transcribes audio
  -> useSpeechRecognition emits final transcript
  -> useVoiceOrchestrator receives it
  -> emergencyDetector checks for phrases (synchronous, zero latency)
  -> IF emergency: EmergencyOverlay + TTS emergency message
  -> ELSE: setFaceState('thinking') + getGeminiResponse() [async]
  -> llmEngine: Zhipu -> Pollinations fallback -> offline fallback
  -> { text, positive } response
  -> speak(text), face animates, mouth syncs
  -> setFaceState('idle') after speech

DASHBOARD DATA FLOW:
  ALL dashboard data is MOCK (static constants). No real backend.
  Pain charts use hardcoded data. Alerts are hardcoded.

8.7 useVoiceOrchestrator.ts (8,690 bytes, 249 lines)
------------------------------------------------------------------------
THE MASTER HOOK. Wires STT -> Emergency Check -> LLM -> TTS.

DEPENDENCIES:
  useSpeechRecognition, useSpeechSynthesis, faceStore, voiceStore,
  emergencyDetector, llmEngine, soundEffects

CONSTANTS:
  THINKING_DELAY_MS = 0 (no artificial delay)

CONTINUOUS MODE:
  isActiveRef (useRef) - tracks if session is active.
  User presses mic ONCE to start, ONCE to stop.
  Auto-restarts listening 600ms after each response ends.

MOUTH SYNC via handleWordBoundary:
  Called on each word event. Every 4th word opens wider (emphasis).
  setTimeout decays openness naturally.

5 useEffect HOOKS IN ORDER:

  1. isListening effect:
     isListening=true -> faceState='listening', isMicActive=true,
     voiceError=null, playStartSound()

  2. isSpeaking effect:
     isSpeaking=true  -> faceState='speaking'
     isSpeaking=false AND !isListening -> after 300ms:
       faceState='idle', mouthOpenness=0, isMicActive=false

  3. Error effect:
     error -> map to SPEECH_ERROR_MESSAGES -> setVoiceError(msg)
     faceState='concerned', isMicActive=false, playErrorSound()

  4. TRANSCRIPT EFFECT (core processing loop):
     transcript arrives -> setIsMicActive(false)
     addMessage({role:'patient', content:transcript})
     detectEmergency(transcript)  [SYNCHRONOUS - no network]
       IF emergency:
         setIsEmergency(true), faceState='concerned'
         playEmergencySound()
         addMessage(EMERGENCY_RESPONSE)
         speak(EMERGENCY_RESPONSE) -> RETURN
       ELSE:
         faceState='thinking', playThinkingSound()
         [async] getGeminiResponse(transcript, conversation)
         setLastResponse(text), addMessage({role:'assistant',...})
         If positive: faceState='happy', wait 400ms, speak(text)
         If not positive: speak(text) immediately

  5. Auto-restart effect:
     !isListening AND !isSpeaking AND !error AND isActiveRef.current
     -> setTimeout 600ms -> startListening()

TOGGLE FUNCTION:
  ON:  isActiveRef=true, startListening()
  OFF: isActiveRef=false, stopListening(), cancelSpeech(),
       faceState='idle', mouthOpenness=0, isMicActive=false

RETURNS: {interim, transcript, isListening, isSpeaking, isUnsupported, toggleListening}

8.8 useSpeechRecognition.ts (4,814 bytes, 153 lines)
------------------------------------------------------------------------
Wraps browser Web Speech API SpeechRecognition.

BROWSER DETECTION:
  Checks window.SpeechRecognition and window.webkitSpeechRecognition.
  null if unsupported (isSupported=false).

CONFIGURATION:
  rec.continuous = false      (one utterance at a time - more reliable)
  rec.interimResults = true   (live partial text)
  rec.lang = 'en-US'
  rec.maxAlternatives = 1

EVENT HANDLERS:
  onstart: isListening=true, clear error/transcript/interim
  onresult: separate final vs interim; setTranscript on final, setInterim on interim
  onerror: map via ERROR_MAP; 'aborted' is ignored (intentional stop)
  onend: isListening=false, interim=''

Recognition instance created ONCE in useEffect, stored in ref.

ERROR_MAP:
  'not-allowed'   -> 'not-allowed'
  'no-speech'     -> 'no-speech'
  'audio-capture' -> 'audio-capture'
  'network'       -> 'network'
  'aborted'       -> ignored (user stopped intentionally)
  else            -> 'unknown'

RETURNS: {transcript, interim, isListening, isSupported, error,
          startListening, stopListening}

8.9 useSpeechSynthesis.ts (7,143 bytes, 224 lines)
------------------------------------------------------------------------
TTS with two tiers:
  Tier 1 (premium): ElevenLabs API + real audio-driven lip-sync
  Tier 2 (fallback): Browser Web Speech API + word boundary events

VOICE SELECTION (Web Speech, priority order):
  1. Microsoft natural voices (Edge/Windows)
  2. Google voices (Chrome)
  3. Named: Daniel, Alex, Tom, Fred, Aria, Samantha, Victoria
  4. First available voice matching language
  Arabic: filters by lang.startsWith('ar')

LANGUAGE DETECTION:
  Count Arabic chars (U+0600-U+06FF).
  If >30% of text is Arabic chars -> use 'ar' voice/language.

ELEVENLABS INTEGRATION:
  POST https://api.elevenlabs.io/v1/text-to-speech/{voiceId}
  Model: eleven_multilingual_v2 (English + Arabic)
  Settings: stability=0.65, similarity_boost=0.75, style=0.25,
            use_speaker_boost=true
  Process:
    1. Get audio blob from API
    2. Decode with AudioContext.decodeAudioData()
    3. Create AnalyserNode (fftSize=256, smoothing=0.6)
    4. RAF loop reads frequency bins 2-50 (speech range ~200-4000Hz)
    5. avg > 15 -> fire onBoundary() -> drives mouth openness
  TRUE lip-sync from actual audio - not just word boundary events.
  AbortController enables cancellation mid-speech.

WEB SPEECH FALLBACK settings:
  rate=0.82, pitch=1.04, volume=1.0

15. POTENTIAL BUGS AND KNOWN ISSUES
================================================================================

BUG 1: POLLINATIONS PROXY MISSING IN PRODUCTION
Severity: HIGH
The Vite proxy only exists during 'npm run dev'. Production builds have
no proxy. Direct calls to text.pollinations.ai may fail due to CORS.
Impact: If Zhipu fails in production, Pollinations fallback also fails.
Only offline simpleResponseEngine remains.
Fix: Deploy a backend proxy endpoint server-side.

BUG 2: EXPOSED API KEY IN BROWSER BUNDLE
Severity: HIGH (Security)
VITE_* variables are compiled into client-side JS. The Zhipu key is
visible to anyone who inspects the built JS files or Network tab.
Impact: Key theft, unauthorized usage, billing charges.
Fix: Move AI calls to a backend proxy. Never put paid keys in VITE_* vars.

BUG 3: ARABIC EMERGENCY DETECTION MISSING
Severity: HIGH (Patient Safety)
emergencyDetector.ts only has English phrases. Arabic speakers saying
emergency words will NOT trigger the emergency workflow.
Impact: Emergency not detected for Arabic-speaking patients.
Fix: Add Arabic emergency phrase translations to EMERGENCY_PHRASES array.

BUG 4: STRICTMODE DOUBLE-RENDER SIDE EFFECTS
Severity: MEDIUM (Development Only)
React 19's StrictMode renders components twice in dev. Animation hooks
and sound effects may initialize twice.
Impact: Development only. Not present in production builds.
Fix: Ensure all useEffect cleanups cancel RAF loops, timers, and audio.

BUG 5: SPEECH RECOGNITION LANGUAGE FIXED TO ENGLISH
Severity: MEDIUM
useSpeechRecognition.ts uses lang='en-US' always. Even though TTS
auto-detects Arabic, mic transcription is English-only.
Impact: Arabic patients cannot use voice input effectively.
Fix: Add language selection or detect intent; set rec.lang='ar-SA'.

BUG 6: MOUTH ANIMATION CONFLICT
Severity: LOW-MEDIUM
useSpeakingMouth (RAF loop) and handleWordBoundary (word events) both
write to mouthOpenness during 'speaking' state. ElevenLabs AnalyserNode
is a third writer. All three compete.
Impact: Jittery or inconsistent mouth animation.
Fix: Only run one mouth driver at a time (feature flag per provider).

BUG 7: NO POLLINATIONS FALLBACK FOR GEMINI BRANCH
Severity: LOW
If user configures Gemini and it fails, it throws directly to the outer
catch (offline fallback) without trying Pollinations first.
Fix: Add try/catch around callGemini() -> callPollinations() fallback.

BUG 8: CONVERSATION HISTORY NOT PERSISTED
Severity: LOW
voiceStore.conversation is in-memory only. Page refresh clears history.
Impact: No session continuity.
Fix: Zustand persist middleware with localStorage.

BUG 9: DASHBOARD TABS ARE NAVIGATION-ONLY
Severity: LOW (UX)
Patients, Alerts, Settings tabs update activeTab state but no content
renders for them. You always see the Overview content.
Fix: Add conditional content sections based on activeTab value.

BUG 10: TYPEWRITERTEXT INTERVAL ON RAPID UNMOUNT
Severity: LOW
If parent unmounts rapidly (switching to Dashboard mid-speech), the
setInterval cleanup runs but may fire one final state update.
Impact: Possible React warning about unmounted component state update.
Fix: Use mounted ref pattern to guard state updates.

BUG 11: AUDIOCONTEXT BLOCKED BY BROWSER AUTOPLAY POLICY
Severity: LOW
Some browsers block AudioContext until user interaction. Code checks for
'suspended' state but may still fail on strict browsers.
Impact: No sound effects on very first interaction.
Fix: Resume AudioContext inside first confirmed user gesture handler.

BUG 12: ELEVENLABS CONCURRENT REQUEST RACE
Severity: LOW
Very rapid speech may start two ElevenLabs requests nearly simultaneously.
AbortController cancels previous but there is a small race window.
Impact: Brief audio overlap or delayed lip-sync.
Fix: Ensure abort fires before new fetch begins (not just 'around same time').

BUG 13: PAIN TREND CHART SAME FOR ALL PATIENTS
Severity: LOW (UX/Accuracy)
PAIN_TREND_DATA is a single constant. All patient modals show identical chart.
Impact: Misleading data in clinical context.
Fix: Add individual trend data arrays to each patient in MOCK_PATIENTS.

16. SECURITY NOTES
================================================================================

1. API KEYS IN CLIENT BUNDLE
   All VITE_* vars compiled into client JS. Zhipu key visible in devtools.
   Action: Use backend proxy for production. Never put paid keys in VITE_*.

2. NO AUTHENTICATION
   No login or session management. Anyone with the URL can access everything.
   Action: Implement role-based auth before hospital deployment.

3. PATIENT PRIVACY / HIPAA
   Voice audio text sent to third-party APIs (Zhipu, Pollinations, ElevenLabs)
   over HTTPS. No persistent patient voice storage in current implementation.
   HIPAA compliance requires Data Processing Agreements with these providers.
   Action: Legal review and DPAs before any real medical use.

4. HTTPS REQUIRED IN PRODUCTION
   Web Speech API requires HTTPS. http:// silently disables microphone.
   Action: Ensure SSL/TLS certificate on deployment server.

5. CORS EXPOSURE
   All AI calls made directly from browser. API credentials visible in
   browser Network tab. CORS relies on third-party service policies.
   Action: Move all AI calls to server-side proxy.
